# jubeat 实机视频抄谱

处理用户提供的 jubeat 实机录屏，整理可复核的音符时间、提取并校准音乐，最后按用户指定格式交付。自动识别只用于生成候选；最终谱面必须能回到原视频逐项核对。

## 工作流程

1. **盘点输入。** 列出视频、现有谱面、曲名对照和用户要求的输出位置。用 ffprobe 检查视频时长、帧率、时间戳和全部音轨；不要假设 MOV 只有一条音轨或恒定帧率。先确认画面中的 4×4 面板方向与谱面索引的映射。
2. **提取候选。** 以原始帧时间戳检查每个面板在音符触发时的视觉变化。可按颜色、亮度或局部纹理生成候选，但不要把固定采样率、亮度阈值或画面峰值延迟套用到所有录制。保留候选时间、面板编号、证据帧和置信度；将同时触发的多个面板分别记录。
3. **校准视频、谱面和音频。** 如果用户提供同曲已知谱面，先从视频音轨中识别与参考 BGM 对应的轨道，再用波形互相关等可复核方法测量音频相对视频的偏移。用多个面板和多个音符，把已知谱面事件与可见触发对应起来，估计该录制的画面响应延迟。记录偏移的符号、参照时间轴、匹配数量和误差分布；不要沿用其他机器或录制的固定常数。若录制有剪辑、变速或时钟漂移，分段检查并明确标注。
4. **逐项复核。** 把候选事件叠到逐帧画面或时间轴上，逐段检查开头、结尾、密集段、同拍和弦、弱闪、遮挡以及容易混淆的面板。每个识别出的音符都应在原视频中找到对应证据；对模糊处保留待确认标记，不用邻近节奏补造音符。复核后检查漏键、重复键、错误面板、排序、音符总数，以及首末键和音频的相对位置。
5. **制作音频与曲目资料。** 保留从录制中提取的原始音轨。需要可播放曲目音频时，依据画面和参考曲目确认起止点后再裁切；记录裁切前后的时间与偏移，不用静音检测单独决定音乐边界。曲名、艺人、版本、封面优先采用官方公开来源；记录可访问来源和获取日期。找不到可靠资料时标为未知，不猜测。
6. **导出并核验。** 先保存逐音符绝对秒数作为权威时间数据，再转换成用户指定的格式。若目标是本仓库支持的目录曲库，遵循 [浏览器目录格式说明](../../../docs/browser-library.md)；视频转录必须标记为 `video_transcription`，不能伪称原始街机 EVE、SEQ 或 300 Hz tick 数据。检查音频可完整解码、谱面面板索引有效、事件按时间排序、音符数量一致、封面与元数据引用有效，并可从包中读回文件。

## 交付内容

至少交付用户要求的曲目音频和谱面；同时保存逐音符时间与面板编号的可读副本，以及校准和复核摘要。摘要说明视频与音频偏移、画面响应延迟、匹配及未确认事件、音符总数、音频时长、元数据来源和已完成的校验。若用户只要一种通用格式，选择可编辑且保留逐音符秒数的格式，不要擅自将其包装成原生游戏资源。

用户的原始视频、音频、提取物和真实谱面只在用户指定的位置处理。它们不得加入公开仓库的示例、测试、截图、日志或提交；公开示例应使用人工合成数据。
