# jubeat 实机视频抄谱

处理用户提供的 jubeat 实机录屏，整理可复核的逐音符时间和键位，提取并校准音乐，最后按用户指定格式交付。自动识别只生成候选；最终谱面必须能回到原视频逐项核对。

## 工作流程

1. **盘点输入。** 列出视频、现有谱面、参考原生谱、曲名对照和输出位置。用 ffprobe 检查时长、帧率、时间戳和全部音轨；不要假设 MOV 只有一条音轨或恒定帧率。先确认 4×4 面板方向与谱面索引的映射。
2. **提取候选。** 按原始帧时间戳检查每个面板的触发变化。颜色、亮度和局部纹理只能作为候选证据，不要把固定采样率、阈值或画面峰值延迟套用到所有录制。保留候选时间、面板编号、证据帧和置信度；同拍和弦逐键记录。亮度峰、白字峰可能落在动画平台的不同位置，反光会使同押相差数帧；不要将每个面板独立估算的时间直接当成最终判定时间。
3. **校准视频、谱面和音频。** 先确认视频音轨与参考 BGM 对应，再用波形互相关等可复核方法测量音频相对视频的偏移。用多个面板、多个音符估计该录制的画面响应延迟；记录偏移的符号、两条时间轴、匹配数量、误差分布。检查各段是否剪辑、变速或时钟漂移，不沿用其他录制的常数。
4. **有原生 MIDI 时做逐键核对。** 从 MIDI tempo map 还原真实秒数；同 tick 的 tempo 事件覆盖默认 tempo。先确认该格式的 pitch→面板映射，才与视频精确事件比较。仓库工具 `python3 -m workflows.video_chart_audit --midi reference.mid --events EXT.events.json --output audit.json` 报告键数、逐键键位差异、视频减 MIDI 的中位偏移、去除整体偏移后的 95% 分位时序误差和重复难度轨。若已经用音频互相关测得旧音频比参考音频晚 0.0495 秒，再加 `--audio-offset-seconds 0.0495`，把音频裁切起点差异与真正的谱面残余偏移分开。键数一致不能证明键位正确；整体偏移接近零也不能证明每个音符准确。排序可能被近邻音符的抖动打乱；对差异处检查原视频帧和同拍和弦，不盲目按序号自动替换。
5. **检查参考资源本身。** 对 BSC、ADV、EXT 按完整事件序列比对；若低难度与 EXT 完全相同，即使配置标了不同等级，也按待核实的复制轨处理，不公开为独立谱面。若参考 MIDI 的音符类型、长押尾部或画面时间轴不清楚，先分析格式或保持未知。不要把来源文件存在当作准确性的证明。
6. **重建同押并逐项复核。** 先读 [同押与音频复核细则](references/chords-and-audio.md)。优先利用完整 marker 动画、该曲节拍及已有谱校准共同估计判定时刻；按证据确认同押后，为组内各键写入完全相同的时间与目标格式节拍。不要用放宽邻近时间阈值来代替重抄。将候选事件叠到逐帧画面和时间轴，检查开头、结尾、密集段、和弦、弱闪、遮挡及容易混淆的面板。逐音符找视频证据；模糊处保留待确认标记，不用邻近节奏补造音符。复核漏键、重复键、错误面板、排序、首末键与音频相对位置。记录错误键位清单、匹配覆盖率、整体偏移及残差分布；对大于一帧的残差和分段漂移重点复看。
7. **制作音频与资料。** 用户要求试听或去投币声时，按 [音频复核细则](references/chords-and-audio.md#试听和杂音处理) 提取真实试听、定位实际音效并保留处理前版本。先统一解码后的音频时间原点，再裁切并用波形检查导出起点，避免容器 seek 引入录制相关偏差。保留录制中提取的原始音轨。裁切可播放 BGM 时，依据画面和参考曲确认边界，记录裁切前后时间与偏移，不单靠静音检测。曲名、艺人、版本、封面优先采用可靠来源并记载出处；未知则标未知。
8. **导出并核验。** 先保存逐音符绝对秒数，后转换目标格式。目标为本仓库目录曲库时遵循 [浏览器目录格式说明](../../../docs/browser-library.md)。视频转录标记 `video_transcription`，不能伪称原始街机 EVE、SEQ 或 300 Hz tick；纳秒容器分辨率不代表视频拥有纳秒准确度。若经核实改用原生谱，保留原视频抄谱及逐键审计作为来源记录，并明确新谱的原生格式。检查音频可解码、键位范围、事件排序、音符数、长押和媒体引用，并从交付包读回。用实际播放器解析交付文件，核对同押分组及快速连键，而不只是 JSON 能否打开。原始检测、修正后的事件侧表和播放器谱面分别保留并注明用途；修正应同步侧表、谱面和索引，排序稳定，不能只改变显示。

## 交付内容

交付用户要求的音频和谱面，并保存逐音符时间、面板编号、证据与校准摘要。摘要包含音视频偏移、画面响应延迟、逐键差异、未确认事件、音符数、时序残差、音频时长、元数据来源及校验结果。没有独立谱面的难度明确标缺失，不复制其他难度充数。

用户原始视频、音频、提取物和真实谱面只在用户指定位置处理，不得加入公开仓库的示例、测试、截图、日志或提交。公开测试只使用人工合成数据。

## 发布与完成状态

只有用户要求上传或现有授权涵盖发布时，才更新线上站点。先验证本地曲包，读取线上索引与待替换文件的当前校验值，备份后合并目标曲目；保留无关曲库和资源。更新缓存资源时发布新的内容哈希文件及索引，避免覆盖旧的哈希文件。通过公开网址校验实际返回的谱面、音频、试听和封面；“上传成功”不是播放验证。

区分候选识别、自动复核、已检查的画面分歧、原谱独立验证和听感复核。报告验证覆盖范围及剩余不确定性，不把参考两曲通过、键数一致、模型置信度、文件校验通过或无新增弱信号当作整批逐键准确的证明。用户指出系统性错误时，回到原视频的帧与动画证据重新估计，保留旧版和分歧记录；不要只打补丁后反复宣布全部完成。
