# 街机 / PC 歌曲 IFS

适配已验证过的 jubeat 歌曲 `_msc.ifs`。输入是本地取得的资源目录；这份脚本不负责通用容器解包、程序解密、下载游戏或启动游戏。

第一次阅读可先看 [完整事件到 JSON 的导读](walkthrough.md)。本页对应源码 [arcade/import_ifs.py](../arcade/import_ifs.py)，重点解释 IFS 地址和音频采样怎样计算。

## 定位与分块

8 位曲目 ID 为 `mid`，路径为：

```text
data/ifs_pack/d<mid前7位>/<mid>_msc.ifs
```

文件 `0x10` 处读取一个 BE32 基准偏移。基准前 60 字节是五条分块记录，每条 12 字节，前两个 BE32 分别是相对偏移和长度。区块地址为基准偏移加相对偏移。

“BE32”是四字节大端无符号整数，例如 `00 00 00 80` 为 128。代码中的变量 `table_off` 实际用于**数据基准**，表的起始地址是 `table_off - 60`，读代码时不要混淆：

```text
base = BE32(file[0x10 : 0x14])
row = base - 60 + 12 * block_index
relative = BE32(file[row : row+4])
size = BE32(file[row+4 : row+8])
payload = file[base+relative : base+relative+size]
```

每行还有第三个四字节字段，当前实现不读取、不解释；不能仅凭位置给它命名成校验和或标志。人工测试中该字段设为零，是构造测试的选择，不表示真实文件必然为零。

| 区块 | 内容 |
|---|---|
| 0 | 完整 BGM，Konami BMP / OKI4S ADPCM |
| 1 | 试听音频；`--with-preview` 可导出 |
| 2 | EXT |
| 3 | ADV |
| 4 | BSC |

读入前限制 IFS 大小，读取各块前校验边界。极小的谱面块可能是未配信占位，返回失败。

人工样例使用 `base=0x80`，五行表从 `0x44` 开始。BGM 占 48 字节、试听块为空，所以 EXT 相对偏移为 `0x30`，绝对地址为 `0xb0`。空试听块和固定基准都是样例设计；实际解析读取文件字段，不硬编码这些数。

为什么这一方法不是通用 IFS 解包？它利用了已验证歌曲包的五块顺序，没有完整解析 IFS 的文件名目录、其他变体与所有元数据。需要扩展适配时应先验证布局，不能认为任意 `.ifs` 都恰好有这五块。

## 谱面与时间轴

谱面块是 CP932 文本，记录一般为 `tick,命令,值`。关注 `TEMPO`、`PLAY`、`LONG`；`HAKU`、`MEASURE`、`END` 作为事件识别，但不输出为 playable note。

`TEMPO` 从 tick 0 开始，tick 频率为 300 Hz。BPM 值是 `60000000/BPM` 的整数截断，转换时寻找可回推到该整数的短小数。按 BPM 分段积分得到拍值，按 1/48 拍取整。

`LONG` 的位置、方向、长度和持续时间位段见 [移动版说明](mobile-format.md)。输出不把量化后同拍的长押降级成单点。

具体例子：tick 0 的 `TEMPO,500000` 表示 120 BPM，tick 600 的 `TEMPO,1000000` 切到 60 BPM。tick 900 的 `PLAY,2` 便在第 5 拍、面板 2；把全程套用初始 BPM 会错放到第 6 拍。推导与 JSON 见 [导读的时间轴部分](walkthrough.md#6-为什么-tick-要先转秒再转拍)。

当前文本解析采用 CP932 替换式解码，会跳过某些字段不足或整数转换失败的行；已读出的未知命令也不生成音符。短于 32 字节视为占位是当前工具的启发式规则，并非已证明的全格式规则。

`.mc` 并非逐 tick 无损格式。若后续用途需要准确还原游戏事件时间，应保留原始输入，不要用 `.mc` 拍值代替原始 tick。

## 音频

Konami `BMP\0` 不是位图或 PCM；本工具处理该格式的 OKI4S ADPCM。读取采样率、声道数和样本数，再按半字节解码为 16-bit PCM。立体声时高 4 位为左声道、低 4 位为右声道。

### 音频头告诉解码器怎样分配数据

| 偏移 | 当前解释 | 当前用途 |
|---|---|---|
| `0x00` | `42 4d 50 00`，即 `BMP\0` | 确认音频类型 |
| `0x04` | 样本帧数 BE32 | 一帧含每个声道各一个采样 |
| `0x08` / `0x0c` | 循环起点 / 终点 BE32 | 读入但不用于输出循环 |
| `0x10` | 声道信息 | 已支持单、双声道；通常直接读取此处一个字节 |
| `0x14` | 采样率 BE32 | 决定每秒播放多少帧 |
| `0x20` 起 | ADPCM 半字节流 | 解出实际 PCM |

其余字段没有完整解释。声道读取保留了首字节为零时尝试 LE16 的分支，不应由此推断完整头部类型定义。若声明帧数为零或大于可用数据，当前代码按可用数据帧数处理；这是容错策略，不是对头部正确性的证明。

### ADPCM 记录的是变化，不是绝对振幅

每个声道保留两个状态：上一个重建采样 `hist`，以及步长表下标 `step_index`，开始都为零。四位编码中的高一位表示正负，低三位表示变化量。较大的变化会提高后续步长，使四位编码也能跟随大幅波形变化。

当前实现的步长表有 **49 项，下标 0..48**，第一项是 16。对每个半字节 `code` 执行：

```text
delta = STEP_SIZES[step_index] << 4
change = delta >> 3
若 code 的 bit 0 为 1：change += delta >> 2
若 code 的 bit 1 为 1：change += delta >> 1
若 code 的 bit 2 为 1：change += delta
若 code 的 bit 3 为 1：change = -change

hist = clamp(hist + change, -32768, 32767)
step_index = clamp(step_index + STEP_DELTA[code], 0, 48)
输出 hist 为一个 16 位有符号小端采样
```

`STEP_DELTA` 的正负两组都为 `[-1,-1,-1,-1,2,4,6,8]`。更新表下标后影响的是**下一个**采样；不能先更新步长再计算当前采样。

立体声的左右声道各维护一套状态。一字节的高半字节给左声道，低半字节给右声道；单声道则按高、低的顺序连续输出两个采样。

### 手算一个字节 `0x10`

初始 `hist=0`、步长为 16，放大到 16 位 PCM 尺度后的 `delta=256`：

| 声道 | code | 本次变化 | 输出采样 | 新步长下标 |
|---|---:|---|---:|---:|
| 左 | 1 | `256/8 + 256/4` | 96 | 0（减 1 后限幅） |
| 右 | 0 | `256/8` | 32 | 0（减 1 后限幅） |

交错输出的 PCM 字节便是 `60 00 20 00`。如果下一字节还是 `0x10`，此时接着各自的历史值计算，输出变成左 192、右 64；不能每个字节都从零开始。因此，从数据中间任意切一段并重置状态，会与连续解码结果不同。

### PCM 到可播放文件

PCM 只有采样值；代码用 `wave` 补上采样率、声道数等头部形成 WAV，再交给 `oggenc` 或 ffmpeg 编成 Vorbis。这个步骤与 IFS 分块读取、ADPCM 解码分别独立，可以各自检查。

默认只解码和转 Vorbis，不主动改变电平。可选 `--target-rms-db` 做 RMS 归一化；有损转换可能改变波形，建议保留原始输入。`--charts-only` 完全跳过音频处理。

`--with-preview` 对区块 1 使用同一套 BMP/OKI4S 解码和音频编码流程，保存为
`.mcz` 内的 `0/preview.ogg`。它保留游戏自带的试听内容，不从完整 BGM 截取，
也不假定固定十秒长度。区块为空时跳过；非空块无效时整曲转换失败。
返回统计包含 `preview_bytes` 和 `preview_status`（`exported`、`absent`、`not_requested`）。
若显式设置目标 RMS，同样应用到试听；默认保持各自解码电平。

启用归一化时，用 `20*log10(sqrt(mean(sample²))/32768)` 估计 RMS dBFS，再乘以 `10^(增益dB/20)` 并限制到 16 位范围。实现还使用历史的 0.45 dB 编码补偿，编码后复测，偏差超过 0.15 dB 时从原 PCM 调整后再编码一次；这些是导出电平的工程参数，不属于 IFS 或 ADPCM 格式。大增益仍可能削波。

ADPCM 本身已经丢失了原始录音的一部分信息；解码得到的是可重建的 PCM，再转 Vorbis 又增加一次有损编码。正确解码不等于恢复压缩前的录音。

## 元数据与打包

IFS 谱面块本身不能满足本脚本需要的全部标题、艺人、版本和等级信息，因此由调用者提供 `--songs` JSON。结构见 `examples/arcade-songs.example.json`；示例中的 ID 与标题均为虚构。

封面可由 `--covers` 指向自己的 PNG 目录。本仓库不提供官方曲目清单、封面或其他提取物。

元数据校验包含 ID、等级和版本目录。输出以曲目 ID 作文件名后缀，解决相同标题与大小写撞名。ZIP 在临时文件写完后才发布，失败不会留下看似完整的 `.mcz`，已有文件不覆盖。`--dry-run` 检查三难度是否能解析，但不测试音频编码器。
